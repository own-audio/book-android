# Emulator test, 2026-11-22

A hands-on pass over phases B4–B13 and the user guide, done as a listener would, on the Android
emulator (Pixel-class phone, 1080 × 2424, 420 dpi, Android 16, API 37) with the Google Play debug
build (0.1.0 (1)), driven with `adb` (`uiautomator dump`, `input`). Media volume was 0 while books
played.

Servers:

| Server | What it is |
|---|---|
| **canary** | own.audio at `api-canary.own.audio` (1.0.7), a member account of a test family that may upload and narrate |
| **old own.audio** | an own.audio test server still on 1.0.0 (v2 revision 0) |
| **ABS** | an Audiobookshelf test server (2.37.1), one book library and three podcast libraries |
| **demo** | the public demo library (Try the Demo Library) |

Everything changed on the servers was put back afterwards: positions reset, favourites and
bookmarks removed, the shared book kept private again, account settings as before, the imported
book deleted, the test sessions signed out. No narration job was started.

The emulator's clock ran five minutes behind real time. own.audio keeps the position with the
newer `at`, so a few position checks against a second session were judged with that in mind.

## Not fixed

|---|---|---|
| ABS | One audiobook of a series failed to download on every file: "The server did not send the file." (`not_audio`). Its MP3s are valid (they play when streamed, `ffprobe` reads them, the server says `audio/mpeg`) but start with 384 bytes of junk before the first frame. | `player/core` `AudioPayloadCheck` accepts an MPEG frame sync only at byte 0. That module is shared with the music and podcast apps. Suggested: when the server says `audio/*` and the head is not JSON/XML/HTML, look for a frame sync within the first few KB. |
| canary | Listening showed 0 min after about 15 minutes of audiobook listening that day. | The Books app (iOS too) reports positions but no plays. The server derives listening from progress only for accounts with no app that reports sessions; this account has such apps. Needs a decision: report plays from Books, or derive per kind. |

Also noticed, not bugs: server chapters of two old narration test books all start at 0 ms (each
file's own time, where v2 says book time), so both chapter rows show as playing — server data;
Media3's notification shows the nearest stock speed icon ("1.8X" for 1.75×); a jump to a bookmark
after a pause applies smart rewind, as book-ios does; Sign In Again leaves the earlier session in
Devices, as book-ios does; the guide's Library page says own.audio has no Collections, but the app
